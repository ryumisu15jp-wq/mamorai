# 現行日報（BHT / ブルガリホテル東京）→ MAMOR-AI マッピングと差分

現行の Excel 日報（【BHT】警備日報_2026年06月.xlsm）を解析し、当システムのデータモデルへの対応と、必要な拡張、そして**最終目標の3成果物（配置予定表・配置表・月次報告書）を実データから生成できること**を実証しました。

## 1. 現行ブックの構造（実測）

| シート | 役割 | 当システムでの対応 |
|---|---|---|
| `原本` / `1`〜`30` | 日次の警備日報（日別1シート） | **テンプレート＋日報レコード** |
| `初期値` | マスタ（氏名・勤務種別・天気・GP色・地震・イベント種別） | **現場マスタ / テンプレ設定** |
| `配置表` | 氏名×日付×勤務区分 の月間グリッド＋区分別人数 | **シフトモデル（ShiftGrid）** |
| `カウント` | 日別の件数集計＋月合計＋稼働率 | **集計（aggregate）** |
| `月次報告書` | 業務対応件数＋対応事案の明細 | **月報生成** |

## 2. 日報（原本）→ テンプレート5セクション

| 原本の項目（実データ） | セクション型 |
|---|---|
| 日付・曜日・天気・報告者・現場・勤務(D/N) | `meta` |
| 勤務時間×警備員（日勤A(責)/日勤B/夜勤A/夜勤B、開始〜終了） | `table` |
| 巡回時未施錠・自火報・ジュエリーケース・不審者/不審物・ELV呼出・緊急呼出・未返却・誤進入・セキュリティカード・入館者/外部スタッフ数 … | `counter` |
| AED点検・消火器点検・鍵点検・FACP点検 | `check` |
| 日勤巡回/夜勤巡回「異常なし」・引継ぎ | `gate` |
| 特記事項・継続不具合事項 | 自由記述（`meta`拡張） |

→ 既に当システムの `resolveForm`/`validateForSubmit`/`createSubmittedReport` がこの構造を扱えます。カウント項目・GP色・天気(日/夜)・稼働率(IN/OUT)・地震/ELV停止は **現場別テンプレのフィールドとして追加のみ**で載ります（NFR-01 準拠）。

## 3. 配置表 → シフトモデル（実証済み）

`配置表` の各セル = その日その隊員の**勤務区分コード**（責/日B/日C/夜A/夜B/臨時/研）。これは当システムの `ShiftCell {staffId, date, workType}` に1対1で対応します。実データ（13名・139人日）を `input-core` に投入し、以下を**実際に計算**しました：

- `monthlyWorkTypeCounts` → 隊員別の区分内訳（例 三角龍彦＝責19/日C6/日B1＝26勤務日）
- `buildDailyAssignment`（6日）→ 責:三角龍彦 / 日B:木村重明 / **日C:欠員** / 夜A:二野宮慧太 / 夜B:山本喜久（原本で6日の日C=0を**欠員として正しく検出**）
- 区分別 延べ人日：責30・日B32・日C22・夜A29・夜B30（原本ヘッダと5/6一致）

## 4. カウント → 月次報告書（実証済み・数値100%一致）

`カウント` の月合計を `月次報告書` に集計。当システムの集計ロジックで**原本の合計と完全一致**を確認：入館者1394・外部スタッフ1137・巡回時未施錠54・自火報1・救急1・不審者4・ELV呼出2・緊急呼出6・未返却3・誤進入1・セキュリティカード20・平均稼働率61.2%。対応事案の明細（自火報/緊急呼出/不審者、日付＋内容）は日報の特記事項から集約します。

## 5. 生成した3成果物（この実データから）

`bht/out/` に生成（Excel＝数式入り0エラー、PDF＝プレビュー）：
- **配置予定表_2026年06月_ブルガリホテル東京.xlsx**（計画＝氏名×日グリッド＋必要人数・充足/欠員の自動集計）
- **配置表_2026年06月_ブルガリホテル東京.xlsx**（実績＝氏名×日グリッド＋区分別人数の COUNTIF 自動集計＋凡例）

## 6. 実装で決めるべき差分（現場ごとに異なる点）

1. **勤務区分＝現場別マスタ**：責/日B/日C/夜A/夜B/臨時/研 と派生（責A・責B・日B-1〜4）は現場ごとに違う。`workType` を現場テンプレのマスタとして持たせる（追加のみ）。
2. **複合シフト・分割シフトの表現（要判断）**：`責/夜A`（1人が日勤責＋夜勤を兼務）や `日B-1〜4`（1枠を複数の半日で分担）は「1人1日1区分」の現行モデルでは表しきれない。→ (a) 1日に複数 `ShiftCell` を許可、または (b) 「配置スロット」概念を導入。**これがシフト設計の要の意思決定**です（この差で 日B の延べが±2ズレました）。
3. **予定 vs 実績**：配置予定表（計画）と配置表（実績）は同構造。`ShiftCell.source = 'plan' | 'actual'` で区別し、実績確定は既存のHITL/上書きで反映。
4. **日報の追加フィールド**：GP色・天気(日/夜)・稼働率(IN/OUT)・地震/地区/ELV停止・継続不具合事項・イベント種別を現場テンプレに追加（追加のみ）。
5. **現場ごとの差**：`テンプレート設定(REQ-024)` で現場別にセクション・勤務区分・カウント項目を切替。「大枠は同じ・現場で違う」を吸収できます。
