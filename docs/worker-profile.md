# 勤務員アプリの設定とプロフィール（0414〜0417）

勤務員アプリの右上⚙から「設定」を開き、警備員名簿に必要な情報を登録する。PIN（パスワード）の変更とログアウトも設定の中にある。
承認が要る項目は「申請 → 本社PC・管理者が承認」で反映し、それ以外は保存するとすぐ反映する。

## 項目と承認
| 区分 | 項目 | 反映 |
| --- | --- | --- |
| 基本情報 | 氏名・ふりがな | **承認後**（氏名は承認で `staff.name` が変わる） |
| 基本情報 | 本籍（都道府県） | **承認後** |
| 基本情報 | 顔写真（1枚） | **承認後** |
| 基本情報 | 本人確認資料の写真（運転免許証・パスポート・健康保険証・その他。種類ごとに1枚） | **承認後**（マイナンバーカードは選べない） |
| 住所 | 現住所・郵便番号・最寄駅 | **承認後** |
| 経歴 | 資格・教育・健康診断（種類・名称・取得日・有効期限・証書の写真） | **承認後**（追加・変更・削除のどれも） |
| 連絡先 | 電話番号・メール | すぐ反映 |
| 連絡先 | 緊急連絡先（氏名・続柄・電話） | すぐ反映 |
| 経歴 | 学歴（10件まで）・業務経歴（20件まで） | すぐ反映 |

生年月日は本社・現場PCが登録した値を表示するだけ（初期PINの元になるため、本人は変更できない）。
**扱わない項目:** マイナンバー・本籍の番地・扶養控除・家族情報・給与口座・社会保険・雇用保険・国籍／在留カード・日雇派遣の例外要件。
給与・税・保険は口座・家族・保険番号を含み、警備の運用の目的から外れるため、給与システム側で扱う。外国籍の勤務員を登録する場合は、国籍と在留期限を後から足す（要望があれば）。
警備員名簿の記載事項は法令・所轄の公安委員会の運用で決まる。実際の様式と項目は、公安委員会か顧問の行政書士に確認すること。

## 申請と承認の流れ
1. 勤務員がアプリから申請（`worker_request_submit`）。同じ項目の承認待ちは新しい申請で置き換わる。取り下げもできる。
2. 管理コンソール「勤務員の個人情報」の「承認待ちの申請」に、**変更前の値つき**で出る。添付の写真は「見る」を押したときだけ読み込む（閲覧が記録される）。
3. 承認すると正式な値に反映される（`company_request_decide`）。差し戻しは**理由が必須**で、勤務員の画面に30日間表示される。
4. 決着した申請の写真は消す（正式な写真は `staff_images` / `staff_id_docs` に移る）。

承認者は本社PC・管理者。支店は担当現場の勤務員の申請だけ。教育センター・現場PCは承認できない（現場PCは見るだけ）。

## 見られる人と記録
- 本人: 端末シークレット（`worker_by_device`）で本人の分だけ。本人確認資料の写真は本人の画面には出さない。
- 本社PC・管理者（会社アカウント）: 自社の勤務員。支店は担当現場の勤務員だけ。教育センターは対象外。
- 現場PC: 自現場に配置された勤務員の基本情報・顔写真・証書の写真。**本人確認資料は見られない。**
- 本人以外が見ると `staff_profile_views`（誰が・何を・いつ）に残る。管理者は直近50件を見られる。

表（`staff_profiles` / `staff_credentials` / `staff_images` / `staff_id_docs` / `profile_requests` / `staff_profile_views`）は anon・authenticated に権限を付けず、すべて security definer の RPC 経由。
承認が要る項目を直接書く旧RPC（`worker_profile_save` / `worker_credential_*` / `worker_image_save|delete`）は、0417 で「申請が必要です」のエラーに置き換えた（承認の迂回を防ぐ。旧画面は失敗するだけ）。

## 画像の保管
Supabase Storage ではなく、DB の表（bytea、1枚約1MBまで。端末で長辺1024〜1400pxのJPEGに縮小してから送る）に保存している。
Storage へ書き込むには、端末シークレットを検証してアップロードURLを出すサーバ（Edge Function など）が要るため。
勤務員が増えて容量が足りなくなったら、サーバを用意して Storage に移す。目安: 100人 × 顔1枚＋本人確認資料1枚＋証書3枚 ≒ 数十〜150MB。

## RPC
- 本人: `worker_profile_get`、`worker_contact_save`、`worker_career_save`、`worker_request_submit` / `worker_request_withdraw`、`worker_image_get`
- 本社PC・管理者・支店: `company_list_staff`、`company_staff_profile`、`company_staff_image`、`company_staff_id_doc`、`company_list_requests`、`company_request_image`、`company_request_decide`、`company_staff_view_log`（管理者のみ）
- 現場PC: `sitepc_staff_profile(p_session, p_staff_no)`、`sitepc_staff_image(...)`

## 画面
- 勤務員アプリ: ⚙ 設定（`apps/desktop/src/pwa/screens/Settings.tsx`）。申請の状況・差し戻し理由が項目ごとに出る。
- 管理コンソール: 「勤務員の個人情報」（権限 `staff_profile`。本社PC・支店・管理者。上下番だけの運用でも使える）。承認待ちの一覧・勤務員の一覧・個人情報の詳細。
- 現場PC: 「勤務員登録」の各行の「個人情報」（見るだけ）。
