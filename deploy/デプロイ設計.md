# MAMOR-AI デプロイ設計（ドメイン構造）

当面 `mamorai.tryangrow.com` サブドメインで運用 → 後日、独自ドメインへ **DNS張替のみ**で移行（URL基点は env 化済みでコード改修不要）。

## URL構造

| パス | 中身 | 配信 |
|---|---|---|
| `/` | サービスページ | 静的 `web/index.html` |
| `/lp` | LP（集客） | 静的 `web/lp.html` |
| `/co/…` | 会社（本社・権限者）アプリ | SPA（`/app/` にrewriteフォールバック） |
| `/s/…` | 施設（現場）アプリ | 同上 |
| `/tradmin/…` | 運営（TRYANGROW）アプリ | 同上 |
| `/api/…` | APIゲートウェイ（Claude鍵秘匿） | 別ホスト（`api.tryangrow.com` 等）へ |

SPAは1つのビルドを `/app/` 配下に置き、`/co` `/s` `/tradmin` は `vercel.json` の rewrite で `/app/index.html` に集約。ルーティングは `EntryRouter` が `window.location.pathname` で系統を判定します。

## ビルドと配信

```bash
bash deploy/build-web.sh      # out/ を生成
# out/ をホスティング(Vercel等)へ配信。out/vercel.json が rewrite/キャッシュを設定。
```

- SPAは `VITE_BASE=/app/` でビルド（`vite.config.ts` が `base` を env 切替）。Tauri(.exe)版は既定 `base='/'` のまま。
- 静的 `web/index.html` `web/lp.html` の相互リンク（`/`, `/lp`, `/co/`, `/s/`, `/tradmin/`）はドメイン相対なので、独自ドメイン移行後もそのまま動作。

## 環境変数（フロント）

`apps/desktop/.env`（`.env.example` 参照）:

```
VITE_APP_BASE=https://mamorai.tryangrow.com
VITE_API_BASE=https://api.tryangrow.com
VITE_SUPABASE_URL=…
VITE_SUPABASE_ANON_KEY=…
```

Claude APIキーやサービスロールキーは**フロントに置かない**（APIゲートウェイ側のみ）。

## DNS

```
CNAME  mamorai   → <ホスティングのエンドポイント>
CNAME  api       → <ゲートウェイのエンドポイント>   # 任意
```

独自ドメイン移行時は、新ドメインの CNAME を同じエンドポイントへ向けるだけ。アプリ側は env の URL 基点を差し替え。

## デュアル配布（.exe ＋ Web）

同一Reactコードを、
- **Web**: `VITE_BASE=/app/` で上記配信、
- **PC(.exe)**: Tauri v2 で `dist/` をラップ（`base='/'`）、
の2形態で出力。ロジックは `@mamorai/input-core` に集約されているため両者で完全共通。
