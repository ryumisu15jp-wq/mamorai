# 現場ごとに違う日報の扱い — 入力/出力分離アーキテクチャ

## 結論
- **HaiTO は Web システム**（Excel連携ではない）。Excelは置き換え対象の元データ。
- MAMOR-AI は「**1つの構造化入力 → N個の現場フォーマット出力**」で現場差を吸収する。
- 出力は **(b) PDF自動生成（既定）** と **(a) 既存Excelへの書き戻し（互換オプション）** の両対応。

## 全体像

```
 [現場A様式]  [現場B様式]  [現場C様式]      ← 現状: 現場ごとにバラバラなExcel日報
      \           |           /
       ▼          ▼          ▼
   ┌───────────────────────────────┐
   │  MAMOR-AI 構造化入力（1分日報）   │   ← 意味は共通(日付/勤務者/巡回/件数/配置)
   │  テンプレート定義＋業態マスタで現場差を吸収 │      現場ごとの差はデータ定義で表現
   └───────────────┬───────────────┘
                   │  共通データモデル(input-core)
        ┌──────────┴───────────┐
        ▼                      ▼
 (b) PDF自動出力〔既定〕     (a) Excel書き戻し〔互換〕
  現場レイアウトへ流し込み     既存ブックをひな型に値だけ差込
  月次/配置表 実証済み        集計式・体裁を保持(セルマッピング定義)
```

## 現場差を吸収する2つの定義（データ、コード改修不要）
1. **テンプレート定義（入力）**：どのセクション/項目/勤務区分/カウント項目を使うか。現場ごとに1レコード。REQ-024テンプレ設定＋業態マスタで実装済み。
2. **出力定義（出力）**：
   - PDF: レイアウトテンプレート（見出し・表・並び順）。
   - Excel書き戻し: 既存ブックの「入力セル↔データ項目」対応表（例 `原本!I10 ← counter.未施錠`）。

## (a) vs (b) トレードオフ
| | (b) PDF自動出力 | (a) Excel書き戻し |
|---|---|---|
| 現場様式の再現 | レイアウトをテンプレ化して再現 | 既存ブックそのまま(式・体裁保持) |
| 崩れ/破損リスク | 低い | 中(セル位置変更・マクロ破損に注意) |
| 提出・印刷 | 最適(Tauriローカル保存/印刷) | Excel運用が続く現場に最適 |
| 保守 | レイアウト定義を管理 | 現場×改版ごとにセルマッピング保守 |
| 推奨 | **既定** | 既存様式を維持したい現場の互換モード |

## 推奨
既定は **(b) PDF自動出力**（人がExcelを手作業で作る工程をなくす＝本来の価値）。**(a) Excel書き戻しは互換オプションとして併設**。どちらも「現場定義データ」を足すだけで新現場に対応（新業態＝コード改修なし、を今日ホテル/交通の2業態で実証）。

## HaiTOとの関係
HaiTOの「新フォーマット日報」＝本設計の"構造化入力"。MAMOR-AIはそこに **出力(現場PDF/Excel)＋配置表・月次・AIシフトの自動生成** を足し、"見る"だけでなく"作る"まで一気通貫にする点で上回る。
