MAMOR-AI 本番運用 手順書

ブルガリホテル東京パイロットを本番稼働させるための手順。DB適用 → 運営アカウント → 初期データ投入 → 各ログイン確認 → フロント本結線 → 運用開始 まで。 凡例 お客様=あなたの操作 / 開発=こちらで実装。

01現在の状態

  • 本番DB（Supabase）に 0400（会社オンボーディング＋各機能テーブル＋RLS＋発行RPC）と 0401（勤務員PIN運用）を適用済み。完了
  • アプリ（4コンソール＋勤務員PWA）は本番 mamorai.tryangrow.com に配信済み。勤務員PWAのPIN運用（初期PIN=生年月日／初回変更強制）も反映済み。完了
  • ただし各画面のデータは現時点ではブラウザ内（localStorage）で動作。端末間共有・恒久保存にはフロントのSupabase結線（後述Step 6）が必要。

02全体の流れ

Step1〜5はデータを用意して「入口が動く」状態にする作業（大半はこちらで用意したSQLを貼るだけ）。Step6でアプリの各画面を実データに結線し、Step7で正式運用に切り替えます。

03手順（ステップ別）

1

DB適用 完了

Supabase → SQL Editor で 0400_production_onboarding.sql → 0401_pin_recovery.sql の順に実行済み。「Success. No rows returned」で正常です。

2

運営(/tradmin)アカウント作成 お客様

  1. Supabase → Authentication → Users → Add user で運営用のメール＋パスワードを作成（例 admin@tryangrow.com）。
  2. SQL Editor で set_platform_admin.sql（メール部分を①のアドレスに変更）を実行し、platform_admin を付与。
  3. mamorai.tryangrow.com/tradmin にメール＋パスワードでログインできることを確認。
3

初期データ投入（会社／現場／勤務員） お客様

SQL Editor で seed_bulgari.sql を実行。これだけで下記が作成されます（冪等・再実行OK）。

  • 会社：ヒトトヒト株式会社（HTH-0001）
  • 現場：ブルガリホテル東京（BVL-01）／現場PIN 1234
  • 勤務員6名：初期PIN＝生年月日の月日（例 三角=0412／藤井=0903／大野=1220／中村=0608／小林=0227／渡辺=1115）、全員「初回変更要」
4

会社(/co)管理者アカウント作成 お客様

  1. Authentication → Users → Add user で会社管理者のメール＋パスワードを作成。
  2. seed_bulgari.sql 末尾のコメント（会社管理者紐付け）のメールを②に変更し、その5行を実行して company_admin＋会社を付与。
  3. /co にログイン → 自社（ヒトトヒト）のデータのみ見えることを確認。
5

各ログインの動作確認 お客様

下の早見表のとおり4系統でログインし、勤務員は初回PIN変更まで確認します（詳細は次章）。

6

フロント本結線（各画面をSupabaseへ） 開発

現在localStorageで動く各画面（有給・シフト希望・講習会・日報取込・勤務員登録・シフト作成・配置）を、Supabaseの実テーブル／RPCへ順に置き換えます。現場・勤務員の業務RPC（提出／承認／一覧）を 0402 として追加し、画面ごとにバインド→本番検証→切替します。ここはこちらで実装し、都度zipでお渡しします。

7

本番運用開始 お客様 開発

端末間反映・RLS分離・帳票出力を実データで確認し、デモ（localStorage）から本番へ切替。以降は会社が自社で現場・勤務員を追加できます。

06セキュリティ・運用の注意

  • service_role キーはサーバ環境変数のみに置き、クライアントやチャットに貼らない（会社管理者のAuthユーザー作成に使用）。
  • 以前チャットに出た GitHubトークンは未実施であれば無効化・再発行を推奨。
  • 勤務員PINは現場での復旧用に現在値を保持（4桁の利便用PIN想定）。より厳格運用が必要なら暗号化方式へ差替可能。
  • 本番切替前に Supabase の バックアップ／PITR 設定を確認。
